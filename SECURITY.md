# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or exposed secret.

Use the repository's **Security → Report a vulnerability** flow. Include the affected component, reproduction steps, impact, and a safe proof of concept when possible. The maintainers will acknowledge the report, assess exposure, and coordinate a fix before public disclosure.

Never include production credentials, private user data, access tokens, or database exports in an issue or pull request.
